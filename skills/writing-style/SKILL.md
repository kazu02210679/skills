# 日本語の認知リズムを整える

## 概要

日本語の説明文を、情報を保ったまま読み進めやすくする。緩急を単なる文長の変化ではなく、読者の認知状態を「観察・仮説・保留・確定・再検討」と移動させる設計として扱う。

文章上の仕掛けは、対象の事実、データ、発言、比較、書き手の判断状態から作る。仕掛けの名前や執筆手順を本文で実況しない。

## 基本原則

### 認知状態を動かす

- 同じ調子の説明を続けず、観察、仮説、ためらい、断定、再観察を切り替える。
- 断定だけで押し切らず、読者が検討に参加できる短い保留や反問を置く。
- 保留は内容に根拠があるときだけ使う。根拠のない曖昧語で責任をぼかさない。
- 書き手が結論へ至る順序を必要な範囲で再現し、完成済みの答えを上から説明する声に固定しない。

### 続きを読む理由を残す

- 答えの出ていない問い、確認待ちの仮説、説明すべき落差のいずれかを一つ開いておく。
- 新しい問いを増やす前に、既存の問いがどこで閉じるかを決める。
- 緊張の材料は対象から取る。本文の予定や構成を語って代用しない。
- 終わりでは主要な問いを閉じる。余韻として残す未決事項は一つまでにする。

### 情報を犠牲にしない

- リズムのためだけに必要な範囲、前提、比較軸、条件、不確実性を削らない。
- 短文を増やすことと、文章を明快にすることを同一視しない。
- 事実、引用、数値、因果関係を新しく作ってドラマを演出しない。
- 材料がない箇所は無理に起伏を作らず、平坦な説明として残す。

## 文と段落を設計する

### 文の拍

段落の基本形を「足場を置く → 展開する → 止める」とする。

- 冒頭の短い文で観点または事実を固定する。
- 中央の長めの文で条件、理由、例外、比較を展開する。
- 最後の短い文で判断、違和感、次に検討すべき対象のどれかを残す。
- 長い断定文が三つ以上続いたら、短い確認、保留、具体例のいずれかを挟めるか検討する。
- 短文が連続して電報調になったら、因果や条件を一文へ戻す。

短文は強調の装飾ではない。読者が今どこに立っているかを固定するために使う。

### 断定と保留

- 根拠が確定している箇所は明確に言い切る。
- 推測、暫定判断、未検証事項は、その状態が分かる語で示す。
- 読者が抱く自然な反問を置いたら、すぐ結論へ飛ばず、一度もっともな理由を受け止めてから転回する。
- 「おそらく」「かもしれない」を均等に散らさない。判断状態が変わる地点だけに置く。

### 段落の密度

- 情報量の多い段落が二、三個続いたら、短い段落で確定事項、次の判定対象、視点距離の変更のいずれかを示す。
- 数値、記録、発言、コードなどへ近づく段落と、それらの意味を捉える段落を往復する。
- 疎な段落にも機能を一つ持たせる。雰囲気だけの一文は置かない。
- 一段落につき中心となる判断を一つにする。複数の結論が競合するなら分ける。

## 境界を設計する

### 冒頭

最初の数文で、読者が確認したくなる落差を一つ作る。

使える入口：

- 読者が知っている感覚を言い直し、そこから仮説を立てる。
- 直感的な期待と、観測された事実のずれを並べる。
- 確信のある命題を置き、本文でその条件を確かめる。
- 読者の具体的な抵抗や反論を先に示し、短く扱う。

議題だけを並べる無色の予告は避ける。範囲の提示が必要なら、なぜその範囲を見るのかという判断と結びつける。

### 節の開始

- 直前に残った違和感を、対象についての問いへ変える。
- 読者が自然に抱く反問から始める。
- 書き手の思い込みや暫定判断を示し、直後の検証につなげる。
- 理論や概念名は、具体的な違和感を読者が認識した後に導入する。

節末で「次は〜を見る」と予告して橋を架けない。次節の冒頭そのものに、反問、観測、判断の変化を置く。

### 列挙

- 列挙の前に、何を区別するための項目かを示す。
- 列挙後は、各項目を直前の事例、データ、判断へ対応づける。
- すべての項目を同じ文型で着地させず、因果、対比、適用、限界を使い分ける。
- 箇条書きの後に要約を置くなら、新しい判断を一つ加える。項目の言い直しだけで終えない。

### 結び

- 抽象的な原則を、冒頭の事実、例、読者の経験のいずれかへ戻す。
- 本文で立てた主要な問いに答える。
- 新しい大論点を結論で持ち込まない。
- 読者へ判断を委ねる場合も、本文から確定できる範囲を先に示す。

## 話題テスト

各文が更新する対象を判定する。

- **状況を更新する文**：対象の事実、データ、人物の発言、比較結果、または書き手の判断状態を新しく伝える。残す候補にする。
- **文書を更新する文**：この章が何をするか、ここまでどう見えるか、次に何を書くかだけを伝える。原則として削る。

文書を更新するだけの文を見つけたら、次の順で処理する。

1. まず削除し、前後がつながるか読む。
2. 論理が飛ぶなら、その文が指していた対象側の情報へ書き換える。
3. 書き換えても本文の進行を実況しているなら削除し、前後の因果を直接つなぐ。

残せるメタ的な文は、次の機能を明確に持つものに限る。

- 読者の具体的な反論を引用して処理する。
- 対象についての問いを設置する、または明示的に答える。
- 冒頭や結びで、読み方に必要な依頼や断りを置く。
- 架空例の開始または終了を示す。

短く勢いのある文でも、文書の進行しか伝えないなら残さない。リズムは話題テストを通った文に対して評価する。

## 執筆後の点検

草稿を最後まで書いてから、次の順で確認する。

1. **事実テスト**：追加した場面、数値、発言、因果に根拠があるか確認する。演出のために作った材料を削る。
2. **話題テスト**：段落の先頭と独立した短文を拾い、状況を更新するか、文書を更新するか判定する。
3. **装置漏れテスト**：「ここで問いを置く」「先に半分だけ答える」「次に見る」のような執筆操作の実況を検索して削る。
4. **問いの台帳**：本文で開いた問い、仮説、約束と、その回答位置を対応づける。回答できないものは問いごと削る。
5. **拍のテスト**：長い断定の連続、短文の連打、同じ語尾の反復を探し、内容に沿って統合または分割する。
6. **密度のテスト**：密な段落が続く箇所に、確定事項か視点変更を担う疎な段落が必要か判断する。
7. **境界テスト**：呼びかけ、断り、謙抑が論証の中盤へ混入していないか確認し、必要なら冒頭か結びへ移す。
8. **文脈テスト**：編集によって必要な前提、条件、比較軸が欠けていないか確認する。

推敲で新しく書いた文も、その直後に事実テストと話題テストへ戻す。

## 症状から修正する

| 症状 | 主な原因 | 修正 |
|---|---|---|
| 正確だが先を読みたくならない | 確認すべき落差や問いがない | 対象の事実と直感的な期待のずれを一つ示す |
| 全段落が同じ調子で疲れる | 文長、判断状態、視点距離が固定されている | 足場・展開・停止を作り、具体と意味づけを往復する |
| 理論の節だけ冷たく見える | 名前が違和感より先に出ている | 具体例で問題を認識させてから概念名を導入する |
| 短文は多いが芝居がかっている | 文書の進行を短く実況している | 話題テストを行い、対象の事実か判断状態へ書き換える |
| 箇条書きが記憶に残らない | 項目が事例へ戻っていない | 各項目を直前の具体へ一つずつ対応づける |
| 冒頭が事務的 | 議題表だけで始まっている | 読者の実感、期待と事実のずれ、具体的な反論のいずれかから入る |
| 結論が説教に見える | 抽象的な一般則のまま閉じている | 冒頭の具体へ戻し、本文の問いに答えて閉じる |
| 読みやすいが情報が足りない | リズムを優先して前提を削った | 範囲、条件、比較軸、不確実性を復元する |

## 例

修正前：

> キャッシュは計算結果を再利用する仕組みである。処理時間を短縮できる。一方で古い値が残ることがある。無効化戦略が重要である。

修正後：

> キャッシュは、同じ計算を繰り返さないための仕組みである。読み出しは速くなるが、その速さは「保存した値がまだ正しい」という仮定に支えられている。問題は、値が変わった瞬間に起きる。再利用の設計は、そのまま無効化の設計でもある。

修正後は、新しい事実を足さず、定義、前提、転回、結論の順に判断状態を動かしている。例を模倣するときは文型ではなく、情報間の関係を使う。

## よくある誤り

- すべての段落を短文で始めて型が見える。
- 問いを増やし、答えを置かない。
- 事実の乏しい箇所に架空の出来事や感情を足す。
- 「ここから重要になる」など、重要さを宣言するだけで内容を更新しない。
- 読者への呼びかけを論証の途中へ何度も挟む。
- 文章を短くするために例外条件や不確実性を落とす。
- 元の文章が求める文体、長さ、対象読者よりリズムを優先する。

最終判断では、読み味より先に正確さと必要な文脈を守る。そのうえで、読者の認知状態が同じ場所に留まり続けていないかを整える。
